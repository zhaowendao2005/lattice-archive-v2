# 聚焦搜索：筛选修复、虚拟视口与加密分页索引

## 实现边界

- `aggregateSearchStore` 是搜索状态、结果、选区、视口和进度的唯一真相来源。
- `focusedSearch.ts` 属于 Store 域异步编排：每会话独立分页，完成一页即可继续，不等待其他会话。
- Telegram 请求仍只走 `TelegramBusClient → BusRouter → SearchBus → RequestScheduler`。没有新增 Telegram dispatcher、RPC 旁路或并发池。
- `worker/local/archive/searchModel.ts` / `searchContracts.ts` 是纯函数与 DTO；架构检查仅为这两个具体模块增加白名单，没有豁免。
- `aggregateSearchIndex` 是到本地索引 Worker 的薄桥。IndexedDB、JSON 解析/序列化、AES-GCM 加解密在索引 Worker 内进行；该 Worker 不接触 Telegram RPC 或主线程 Store。
- DOM、ResizeObserver、滚动 rAF 句柄只在 `searchViewportDataSource` 内持有。

## 正确性

1. 大小输入接受 `string | number`；空白返回 `undefined`，显式 0 保留。非法值、负值、溢出以及最小值大于最大值会阻止新搜索并展示中文错误、展开筛选与聚焦输入。
2. 搜索前类型按可映射类别拆成独立请求单元（视频 / 图片 / 文档各一次 `messages.Search`），结果合并去重；无法映射的类别退回一次 `all` 请求。未知大小不再伪造为照片 250KB；精确体积是搜索结果后的本地条件，只作用于视频与图片，其他类型不受影响。格式按元数据扩展名过滤，不下载文件验证格式。
3. 关键词由 Telegram 匹配；不再用本地子串逻辑二次剔除其命中。索引仅复用可证明相同的候选查询，不推断相近关键词存在包含关系。
4. 单会话分页使用原始消息游标，并持续到服务端空页；DTO 转换丢弃服务消息或短页不再被当成穷尽。游标不前进报告失败，不伪装完成。
5. 每次搜索从头探测新消息，直到与旧索引头重叠，然后回放缓存并恢复历史检查点。刷新未抵达旧头时不能提前推进保存的头，否则停止后会遗漏中间区域。
6. 缓存新鲜期为最近历史推进后的 5 分钟。仅探测新消息不会延长该期限；过期删除该候选查询索引并重新扫描。完整扫描本身不是 Telegram 的事务快照，旧消息编辑/删除需要重新验证；界面提供“忽略缓存，全量复核”立即重扫。
7. 单会话失败不阻塞其他会话；界面区分扫描完成、部分失败、异常与用户停止，不再一律显示“已加载全部”。停止阻止后续派生请求与旧结果回写；已发出的网络请求不能保证物理瞬间撤回。

## 索引

- 淘汰 v1 整账号快照（派生数据，可重建），不双读，不保留兼容管线。首次运行需重新建立本地搜索索引，不影响 Telegram 会话或归档数据。
- v2 每页单独加密，每个候选查询单独保存覆盖头；同一事务提交消息页和检查点，等待事务完成而非单条 put 成功。
- 账号、会话、精确关键词/日期/服务端类型算子构成候选范围；大小、扩展名是元数据本地条件，变化时可复用候选页。已完成不限类型扫描可服务类型收窄。
- 内容、文件名、授权引用与覆盖头在本机 AES-GCM 加密；查找键使用 SHA-256，不落明文关键词。使用设备现有不可导出 CryptoKey，仅向可信本地 Worker structured-clone。
- 每 32 次提交执行回收：4096 页、64MiB 密文软阈值及 7 天保留期。阈值间允许一个回收批次的暂时超出。不是无上限持久增长。
- 淘汰任一页必须使该范围覆盖失效，并保留失效标记，阻止尚在运行的旧扫描重新写成“完整”；下次读取清理残片并重扫。
- 索引不可用时退化为真实网络扫描并记录告警，而不是返回成功的空结果。缓存页读取缺失时该会话报告失败，不能声称完整。

## 渲染与封面

- 中间结果采用 93px 固定行高窗口（HEAD 卡片 85px + 8px 间距）；右侧会话列表按凭据过期状态采用 90px / 109px 变高窗口（前缀偏移定位）。两者都只挂载可视行与上下各 5 行；总数据不截断。选区/Shift/拖拽使用完整结果索引。行高为按 HEAD 样式估算值，需在真实账号下用 DevTools 复测校准。
- Store 维护持续 ID Set，并以 32ms 窗口批量追加；空进度块不再遍历已有结果。
- 搜索后投影只对新增结果执行条件与媒体去重；修改筛选或替换结果源时才重新评估历史。视口只订阅浅列表快照。
- 自动封面仅面向窗口及预加载行；离开窗口、停止、关闭和切换账号会取消请求。取消贯通到主线程封面队列（排队中的任务立即出队）与 Worker 调度器（`busCancel → CoverBus → RequestScheduler` 出队）；已发出的 GramJS 下载无法中途打断，结果丢弃后释放槽位。封面 key 按账号与搜索代际隔离，过期完成不回写。
- 打开聚合搜索不再自动发起检索；空关键词不启动搜索，只提示并聚焦输入框。右栏会话范围按虚拟窗口加载真实 Telegram 头像，缺失时回退为缩写方块。
- 开发者选项监控改用 ECharts：并发 / 请求速率 / 字节吞吐三张独立单轴图，九条总线固定取色、原生图例可隐藏曲线，`dataZoom` 联动选择区间；原始序列按账号常驻内存，绘图经 min/max 降采样。
- 三个预留按钮保留外观并置为 `disabled`；删除重复徽标/角标与逐卡片模糊（外观按 HEAD 深色毛玻璃还原，外壳保留模糊，卡片不加模糊）。筛选菜单与左树按 HEAD 保持常驻 DOM 以保留收起动画，状态留在 Store。
- 删除已接线搜索 Mock 与假凭据回退。原“会话”类型不是消息媒体类型，现由右侧范围选择负责。

## 自动检查

`pnpm test:search` 纳入 `pnpm build`。测试实际纯函数、实际搜索编排（替换传输边界）及 fake-indexeddb 上的真实加密存储实现，包括：

- 空白/数字/0/非法大小，未知照片大小，服务端关键词语义；
- 1k / 10k / 50k 条结果的窗口上界，追加投影仅遍历新项；
- 旧快照淘汰、密文与键隐私、账号隔离、页增量写入、事务回滚；
- 过期、页数/字节阈值、淘汰失效、活动扫描不能复活错误完整性；
- 视频、短页后续、头探测、缓存局部顺序、历史恢复、半刷新停止；
- 慢会话隔离、停止、切换账号、强制复核、索引异常与单会话失败。

另运行 `pnpm arch:check`、`pnpm test:bus`、`pnpm test:scheduler`、`pnpm test:session-parser`、`pnpm build`、`git diff --check`。真实账号和帧率测量由用户端到端验收，不以离线测试替代。

## 用户端到端验收（五组动作）

1. **类型与空白边界**：选 2～3 个已知有视频的群、输入已知关键词。大小均留空先搜不限类型，再只选视频；应均能返回对应内容。显式最大 0 应排除正常视频，不等于不限。
2. **条件输入与校验**：输入小数大小，仅设最小值/仅设最大值，配合 `mp4, mkv` 搜索。确认不会卡在加载态；输入负数或最小值大于最大值应中文报错且不启动新搜索。清空恢复不限。
3. **大量结果与交互**：选多个大群获取大量结果，快速上下滚动、改变搜索后筛选、Shift 连选、全选再拖入目录，并折叠/展开两侧。结果应连续、选择正确、无明显空白错位；DOM 中 `.search-results-viewport article` 数量应近似固定而非随总命中增长。
4. **缓存与复核**：中途停止后同条件重搜，再改变范围/扩展名/大小。应探测新消息并复用覆盖部分；发送新的匹配消息后重搜应能看到。编辑/删除旧匹配消息后，勾选“忽略缓存，全量复核”确认旧结果得到更新。
5. **取消与隔离**：大量搜索/补封面时点击停止，马上换词重搜，再切换账号或关闭重开弹窗。停止后旧结果不再增长，新搜索不混入旧结果/封面。若加入一个无权限会话，应看到该会话失败详情，其余会话继续。

日志观察：`focused_scope_resolved`、`focused_cache_lookup`（hit/headProbe/cachedPages）、`focused_page_ok`、`focused_page_filtered`、`focused_peer_error`、`focused_index_read_failed/write_failed`，不记录关键词、正文、文件名或授权明文。
